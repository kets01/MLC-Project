# Development notes

Working material from the build, kept for the record but **not** part of the
submitted deliverables. The deliverables are the implementation (`src/`,
`include/`, `tests/`, `apps/`, `bench/`), the report under `docs/source/`, and
the reproducibility material referenced from it.

| directory | contents |
|---|---|
| `roadmap/` | the sprint plan the work followed, with per-sprint outcomes |
| `sprint-errors/` | honest logs of what went wrong in a sprint and how it was fixed |
| `tooling/` | project context/design decisions, and the BNNS baseline investigation |

`CLAUDE.md` stays in the repository root because it is a tool configuration
file that is only read from there.

These notes are referenced from the report where a claim depends on them — in
particular the error logs, which record corrections the report itself cites.
